## Context

See `proposal.md` for motivation.

In GOverlay, tools fall into two runtime categories:
1. **Windows/Proton DLLs** (`OptiScaler`, `DLSS Enabler`, `FakeNVAPI`): Run inside Wine/Proton and write log files directly to the game directory using Windows file APIs (e.g. `<GameDir>/optiscaler.log` or `<GameDir>/dlss-enabler.log`). They do not write to Linux stderr.
2. **Native Vulkan/OpenGL Layers** (`MangoHud`, `vkBasalt`, `vkSumi`, `MAKO`, `lsfg-vk`): Run on the host and emit diagnostic messages to `stderr`.

`bgmod.lpr` forks a background logger process (`RunSubprocessLogger`) connected to the game process stderr pipe. Currently:
- `RunSubprocessLogger` misses `mangohud` lines and has no DLSS Enabler hooks.
- It attempts to sync `OptiScaler.log` by an exact case-sensitive path, failing when the DLL writes `optiscaler.log` (all lowercase).
- GOverlay GUI (`overlayunit.pas`) lacks logic to resolve `dlss-enabler.log` when DLSS Enabler is chosen on the upscaler tab.

## Goals / Non-Goals

**Goals:**
- Provide a robust case-insensitive log synchronization routine (`SyncGameDirLogsToCentral`) that copies or merges all tool logs (`optiscaler.log`, `dlss-enabler.log`, `fakenvapi.log`, `vksumi.log`, `vkbasalt.log`, `mako.log`, `lsfg.log`, `bgmod-uninstaller.log`) from `GameDir` into `CentralLogDir`.
- Capture MangoHud diagnostic output from `stderr` into `mangohud.log` in both `CentralLogDir` and `GameDir`.
- Initialize `dlss-enabler.log` and `mangohud.log` with standard header info.
- Enable `GetActiveTabLogFile` in `overlayunit.pas` to detect DLSS Enabler and open `dlss-enabler.log`, and open `mangohud.log` for MangoHud tabs.

**Non-Goals:**
- Modifying upstream tool logging implementations or internal format.
- Parsing CSV benchmark logs generated by MangoHud's benchmarking keybind.

## Decisions

### 1. Case-insensitive log file sync in `bgmod`
**Rationale:** On Linux filesystems, `OptiScaler.log` and `optiscaler.log` are distinct. Wine applications may create either depending on configuration and wine prefixes. Using case-insensitive scanning ensures any tool-generated log in `GameDir` is recognized.
**Alternatives considered:** Forcing Wine case-insensitivity mount options (impractical, requires filesystem or kernel changes).

### 2. Synchronization at process termination in `RunSubprocessLogger`
**Rationale:** `RunSubprocessLogger` runs as a child process monitoring the game's stderr pipe. When the game terminates (normally or by crash), the write end of the pipe closes, causing `fpRead` to return EOF (<= 0). At this exact moment, all files written by the game DLLs are flushed and closed on disk. Executing `SyncGameDirLogsToCentral` here guarantees fresh logs are copied into `CentralLogDir`.
**Alternatives considered:** Polling every second during execution (unnecessary overhead for small logs, but final sync at pipe EOF is 100% reliable).

### 3. MangoHud stderr stream filtering
**Rationale:** MangoHud outputs diagnostic initialization, configuration loading, and error warnings to stderr. Adding a filter for `mangohud` in `RunSubprocessLogger` captures these messages in `mangohud.log` in the same way `mako`, `lsfg`, and `vksumi` are captured.
**Alternatives considered:** Setting `output_folder` in `MangoHud.conf` (that only affects benchmark CSV dumps, not stderr diagnostics).

### 4. UI tab log file resolution
**Rationale:** On `optiscalerTabSheet`, the UI allows toggling between OptiScaler and DLSS Enabler via `dlssenablerRadioButton`. Checking this radio button in `GetActiveTabLogFile` allows "Open Log File" to open `dlss-enabler.log` directly when DLSS Enabler is active.

## Risks / Trade-offs

- **[Risk] Log overwriting or header loss:** Copying `<GameDir>/optiscaler.log` could overwrite the initial header written by `InitToolLogFile`.
  $\rightarrow$ **Mitigation:** Ensure the sync appends or updates gracefully, or copies the DLL log while maintaining session demarcations.
- **[Risk] File locking during game run:** Under Linux, open files can still be read safely.
  $\rightarrow$ **Mitigation:** Read streams with shared read permissions (`fmOpenRead or fmShareDenyNone`).
