# Design

## Context

See `proposal.md` for motivation.
Currently, `TChangelogForm` in `changelogunit.pas` hosts a `TMemo` receiving plain text from `overlayunit.pas` via `GetReleaseNotes(GVERSION)` (which invokes `curl` to query the GitHub releases API). Goverlay runs on LCL-Qt6 across diverse Linux packaging systems (Flatpak, AppImage, AUR, Debian/Ubuntu, Fedora, openSUSE). Any solution must not introduce heavy browser engines or non-standard packages that could break package builds or flatpak sandboxing.

## Goals / Non-Goals

**Goals:**
- Replace `TMemo` with a native `TScrollBox` displaying parsed blocks: headers, bullet lists, plain text, and inline images.
- Resize the dialog to a fixed 680x520 window with dark theme styling consistent with Goverlay's palette.
- Implement background image downloading using existing `curl` tooling and cache images in `~/.cache/goverlay/changelog/`.
- Scale images to fit the content width while preserving original aspect ratios.

**Non-Goals:**
- Full HTML/CSS or web browser engine integration (e.g. WebKit or Chromium).
- Interactive hyperlinks or web browsing inside the modal.
- User-resizable dialog window (keep fixed size as requested).

## Decisions

### Decision 1: Native LCL Block Renderer (`TScrollBox` + `TLabel` + `TImage`) over `TIpHtmlPanel`
- **Choice**: Native LCL components placed dynamically inside `TScrollBox`.
- **Rationale**: `TIpHtmlPanel` (TurboPower Ipro) is an old HTML 3.2 engine that poorly supports modern dark themes, responsive image scaling, and modern HTML tags. Native LCL components provide 100% control over colors, fonts, margins, smooth anti-aliased image rendering, and require zero additional Lazarus packages.
- **Alternatives considered**:
  - `TIpHtmlPanel`: rejected due to poor styling and obsolete rendering.
  - `QTextBrowser`: rejected due to lack of LCL cross-platform encapsulation and complex image network loading hooks.

### Decision 2: Background Image Fetching via Thread with Disk Cache
- **Choice**: Use a background download thread leveraging `curl` to fetch images into `~/.cache/goverlay/changelog/<hash>.png/jpg`.
- **Rationale**: Avoids blocking the main UI thread when opening the changelog. Once an image is downloaded, it is permanently cached so future opens display instantly offline.

### Decision 3: Simple, Robust Block Parser
- **Choice**: Parse lines iteratively into structured block types:
  - `### ` or `## `: Header block (`TLabel`, 11pt, bold, primary accent or white font).
  - `- ` or `* `: Bullet item block (`TLabel` with bullet symbol `• ` and auto-wrap).
  - `<img ... src="..." />` or `![...](...)`: Image block (placeholder container with `TImage`).
  - Blank or other lines: paragraph text or spacing.
- **Rationale**: GitHub release bodies generated by developers and release bots strictly follow these conventions.

## Risks / Trade-offs

- **[Risk] Multiple large images downloading simultaneously** → Mitigation: Use a worker thread queue or bounded downloads, preventing process congestion.
- **[Risk] Corrupt or failed image downloads (offline user)** → Mitigation: Verify downloaded file size > 0 and validate image loading via `try...except`; hide failed image containers gracefully without crashing.
- **[Risk] High DPI / Scaling discrepancies** → Mitigation: Compute layout bounds dynamically based on `ScrollBox.ClientWidth` rather than hardcoded pixel offsets.
